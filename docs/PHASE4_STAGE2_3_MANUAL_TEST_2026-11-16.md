## 修改 1｜尾差补记的 Note 永远是 `balance`
1. 打开 Money Transfer → 🏦 余额对账，输入各 Method 的虚构实际余额。
2. 测试**多余额**：例如 TNG 的实际比账本多 RM30，其他 Methods 都等于账本。系统仍只提示可能遗漏 Income，并提供「填入收入」。
3. 点击「填入收入」，确认关于核查原因的提示。此时**仅预填未保存的 Income 表单**，不立即改账本。
4. 查看 Income 表单：Method = TNG、Amount = RM30.00、Note 必须**恰好为小写英文 `balance`**，不带前后缀或翻译。
5. 使用另一组虚构数据测试**少余额**：例如 BANK 的实际比账本少 RM20。点击「填入支出」后，未保存 Expense 表单也必须预填 Note = `balance`。
6. 对以上两种情况，只有你人工确认并点击原有 Add Income / Add Expense 后才会产生真实（Test 环境的）交易；取消不应新增任何记录。普通 Add Record 的 Note 必须保持原有自由输入行为。
7. 中文、英文分别检查：默认 Note 始终是完全相同的 `balance`，不会自动翻译；Month、Amount、Method 与原有尾差算法都保持不变。

## 修改 2｜三个固定功能入口移至左侧抽屉
1. Windows 浏览器打开 Dashboard，鼠标悬停左边缘。左侧滑出抽屉现在应有 **7 个**入口：✨ 财务回顾，📈 财务模拟器，📊 月度财务对比，🎯 储蓄目标，🗓️ 固定账单，🔎 异常记录复查，🏦 余额对账。
2. 点击左侧 **固定账单**：打开原本完整账单浮窗。可创建虚构账单、改日期、看账单日历、提醒、跳过本期，以及确认已付并自动新增唯一 Expense。不能出现第二份不同的账单管理页面。
3. 点击左侧 **异常记录复查**：打开原本完整复查浮窗。四个独立提醒开关、阈值、记录确认与原有单字段编辑功能必须正常；点击左侧入口时显示全部待复查记录，不被某条通知限定。
4. 点击左侧 **余额对账**：应自动滚动到 **Money Transfer 卡片的余额对账 Tab**，而非新开独立对账浮窗。原有 Money Transfer 表单、历史、Undo 和对账全部保留。
5. 打开右上角 🔔。它现在负责**通知**，而不是三个普通工具入口。通知数量、跳动动画、最多三条可见通知，以及“更多”展开列表都应该保留。
6. 创建/触发一条虚构到期账单提醒。点击右上角该具体通知：必须打开对应账单的原本浮窗，可继续处理本期，不只是跳转到主页。
7. 创建/触发一条虚构异常 Expense（例如 RM600、大额提醒已启用）。点击该具体通知：必须打开**对应这笔记录**的复查浮窗，可「确认无误」或修改字段。
8. 使用测试对账历史触发一条账户差额通知：点击右上角具体通知必须跳到 Money Transfer 的 Balance Check，并选中对应 Method。
9. 若超过三条通知，点击「另外还有 N 条」，铃铛展开列表应显示可点击的**逐条通知**；点击任一项应打开该条的对应内容，而不是一个无关的功能总览。
10. 没有任何通知时，铃铛菜单应显示“目前没有待处理提醒”，但左侧的三个工具入口仍能随时使用。
11. Android 浏览器：左侧 7 项入口过高时应可以**纵向滚动**，保持每项可点，不让内容挤压主页或发生横向溢出。右上角通知列表也可独立纵向滚动。
12. 电脑滑出动画与原有浮窗弹出/关闭保持；Android 点击左侧小标签展开；键盘 Tab 与 Escape 能操作；如果操作系统设置减少动态效果，则保持可用且不强制动画。

## 原有功能回归（必须检查）
- 正常 RM 输入 `100` = RM100.00；Cents Keypad `2455` = RM24.55。
- BANK → TNG RM120 只改变两边 Method 余额，不能改变总 Balance。
- 固定账单「确认已付」仍使用唯一请求 ID，避免同一期重复新增 Expense；账单云端版本冲突保护不变。
- 异常提醒的四个独立开关、阈值、复查状态、用户 RLS、单字段交易编辑与同步不变。
- 自动对账仍先匹配 Transfer，余额多/少部分只预填待确认的 Income/Expense，不自动造假收入或支出。
- 财务回顾、模拟器、月度对比、储蓄目标、新增记录、预算、导入导出、Opening Balance 和 Recycle Bin 均正常。
- 另一个测试账号不能看到本账号的财务数据、账单、异常决定或对账历史。
