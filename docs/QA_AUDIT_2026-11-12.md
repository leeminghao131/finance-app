## Newly verified QA findings
- **QA-001 (P1, fixed in this QA branch):** `addRecord` could throw on rejected network promises without showing the user that the save result was unknown. This may encourage a duplicate retry if the server committed before the response was lost. The fix preserves the form, reports an unconfirmed result and asks for a refreshed record-list check. Note: a frontend pending lock is not server-side idempotency; a future API-level idempotency design would need separate approval and test.
- **QA-002 (P3, fixed in this QA branch):** Two dashboard captions were absent from bilingual display mappings. Added the missing mappings and the new record-save error text.
- **QA-003 (P2, observation, not changed):** In the test environment `user_settings` has an owner-scoped DELETE RLS policy, whereas records/transfers have no DELETE policies. No cross-user data access was seen in static policy inspection. The frontend does not call DELETE for settings in the reviewed paths; consider whether settings DELETE should remain permitted in a future security review. No policy changes authorized.
- **QA-004 (P2, observation):** Supabase Test security advisor reports `auth_leaked_password_protection` disabled (WARN). See https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection . Configuration untouched.
- **QA-005 (P2, limitation):** Snapshot consistency checks compare two complete reads *per table*, not one atomic multi-table PostgreSQL snapshot. Further isolated multi-device testing required; no confirmed data loss.
- **QA-006 (P2, validation pending):** React/Android/Windows browser interactions, actual dual-device races, CSV RPC and RLS authorization with two distinct live test identities have not been executed in this QA pass.
