## 测试前
- 只登录**独立 Supabase Test** 账号，使用虚构数据，并检查页面显示 `TEST MODE`；如果出现真实账号、真实财务记录或生产环境标识，立即停止。
- 只改 `src/FinanceStage2Hub.jsx` 的通知来源及相关旧测试，不改财务数据库、已存的账户差额、转账、Income／Expense、Budgets、Opening Balance 或 Supabase RLS。
- 数据库以前的 `account_checks` 历史仍保存，不因移除提示而被删除。

## A｜确认 Method 差额通知已取消
1. 打开 Stage 2.6 Preview，在左侧抽屉选择「余额对账」。
2. 使用虚构余额制造大额正差额和负差额，保存本次对账快照。
3. 关闭浮窗、刷新浏览器，再查看右上角 🔔：不应因为任何 Method 的差额出现「账户有差额」的跳动通知。
4. 右上角提醒数字以及「另外还有 N 条」只统计**固定账单到期提醒与未确认异常记录**；Method 差额不计入。
5. 打开 🔔 的全部通知列表：不会出现针对 TNG、CASH、BANK、GRAB PAY 或自定义 Method 的余额差额通知。

## B｜确认保留的提醒完全正常
1. 通过独立测试账号建立一条虚构到期固定账单，确认到期后仍会出现跳动提醒，点击具体提醒可打开该账单的原本浮窗并完成原有处理。
2. 建立一条大额测试 Expense、疑似重复或缺少备注的虚构记录（对应异常开关须处于开启状态）。右上角仍显示对应异常提醒，点击后可确认无误或编辑**该笔特定记录**。
3. 如果两类提醒都有多条，右上角最多显示前三条跳动提醒；点击额外提醒可在列表中逐条打开对应对象。关闭任何一类异常开关只影响该类提醒，不能删除真实记录。
4. 如果两种类型都没有待办，右上角不应出现待处理提示，但铃铛入口仍可以点击。

## C｜确认余额对账功能本身毫无变化
1. 左侧抽屉的「余额对账」入口仍可以打开完整浮窗；四个 Method 和自定义 Method 都能输入实际余额。
2. 系统仍按 `实际 − 账本` 计算每个 Method 差额；同时出现正、负差额时，仍能建议 Transfer。
3. 只有你明确确认后才写入真实（**仅 Test**）Transfer；Money Transfer 仍不算 Income／Expense，也不改变总资产。
4. 未匹配完的余额仍会在对账浮窗中显示为待核查差额，并可通过**未保存**的 Income／Expense 表单人工补记，默认 Note 仍为小写 `balance`。
5. 「保存全部余额核对记录」、展开「近期活动／历史对账」仍正常；已存的核对快照不会因移除通知而被删除或覆盖。
